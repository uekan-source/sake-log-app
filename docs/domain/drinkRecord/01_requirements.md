# お酒の記録 — 要件定義

発注者は自分自身。要求の要旨を先に置き、原文（殴り書き）はそのまま引用して後ろに残す。

## 受け取った要求

### 要旨

**課題** ── お店で飲んだお酒のボトルをよく写真に撮るが、その場で美味しいと思うだけで、すぐに忘れてしまい自分の知識になっていない。

**目的** ── 飲んだお酒の特徴を覚えて把握し、お酒に詳しくなることで人生に幅を持たせたい。

**やりたいこと**

1. 飲んだお酒を**その場で調べて保存**したい（主な場面は店）
2. 入力は 2 経路：**ラベルの写真を撮る**／**メニューなどの名前・品種・特徴で検索する**
3. 写真や名前から **AI が銘柄情報を自動で調べて表示し、自分で修正もできる**ようにしたい
4. 記録には項目を持たせたい：**名前・品種・産地・味わい・蘊蓄的な特徴**（ただ保存するだけでは面白くない）
5. **過去に撮りためたラベル写真の取り込み**もしたい
6. **ログイン機能**を持たせ、ログインに意味があるようにしたい（複数ユーザーにするかはどちらでも）

**対象** ── よく写真を撮るのは**ワインと日本酒**なので、この 2 種を深く扱う。ウイスキーなど他の種類は今回やらない。

### 原文（2026-08-20 の殴り書き。書き換えない）

> 一度飲んだワインとか日本酒とかの様々なお酒をその場で調べて保存しときたい。よくお店で飲みに行く時、ボトルの銘柄が置かれて写真を取るが、その場では美味しいと思う一方、すぐに忘れてしまい、自分の知識とかにもなっていない。飲んだお酒の特徴を覚えて把握することにより、お酒に詳しくなり自分の人生に幅を持たすことができると思っている
>
> ラベルを写真をとって保存することもしたいし、メニューなどから検索しても保存できるようにしたい
>
> ただ保存するだけでは面白くないので、お酒の名前、品種、地産、どういう味わいか、蘊蓄な特徴などの項目を設けたい

同日の補足（質問への回答）：

> 過去に撮り溜めた写真の取り込みもしたい

> ログインに意味を持たせたい、複数ユーザーはどちらでも

> よく写真を取るのは、ワインと日本酒だからその2個で

殴り書きに先行してチャットで出ていた要望：

> ログイン機能も持たせるから、ログインする意味があるものがいいし、もし記録するやつだったら、自動で入力される奴がいいよね(写真読み取ったら、AIがそれを調べて表示して、入力もできるような)

> ラベル記録ってあるけど、ラベル以外でも検索したい。例えばお酒の名前がメニューにあってそれをその場で入れたらいろんな情報が出るような。写真以外で、メニューや品種、特徴からもでれたらいいね

## 前提

（空欄にしない。聞いていないなら「未確認」、該当しないなら理由つきで「該当なし」）

- 想定規模：利用者は当面自分 1 人。複数ユーザーにするかは未確定（→ Q8）。新規の記録は月 1 回程度＋過去写真の一括取り込みが一度（**枚数は未確認** → Q6）
- 保存期間：**未確認**（→ Q9）
- アクセス境界：ログインは持たせる（「意味のあるログイン」が要求）。境界の引き方は未確定（→ Q8）
- 既存資産：システムは新規（既存なし）。ただし**過去に撮りためたラベル写真**が手元にあり、これが初期データになる
- 法規制・監査：該当なし（個人の記録で、扱う個人情報は自分のもののみ）。ただしラベル写真を外部の AI サービスへ送信する点は、無料枠の利用規約（入力が学習に使われ得る）に留意する

| # | 質問 | 今回の回答（仮） |
|---|---|---|
| Q1 | 「味わい」「蘊蓄」は AI が調べた**説明**の欄と、自分が感じた**感想・評価**の欄を分けて持ちたい。AI の説明だけでなく、自分の感想も記録する、という理解でよいか | |
| Q2 | 同じ銘柄を別の日に飲んだら「飲んだ記録」は 2 件でき、銘柄の情報（名前・品種・産地）は共通になる、と考えている。あわせて**いつ・どこで（店名）・誰と**飲んだかも記録に持たせたいか | |
| Q3 | メニューで調べたが**飲まなかった**酒は、「飲んだ記録」とは別に「気になる」として残せるようにしたいか。それとも保存しないか | |
| Q4 | 店では「写真を撮る（または名前を入れる）→ 保存」までで終わり、AI の推定結果の**確認・修正は後からゆっくりでもできる**、という形でよいか | |
| Q5 | 「詳しくなる」の手段は、まず**品種・産地・味わいでの検索と一覧**（振り返り）で足りる、という理解でよいか。復習クイズのような機能は今回やらない | |
