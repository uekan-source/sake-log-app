# お酒の記録 — 要件定義

発注者は自分自身。要求の原文（殴り書きと補足の引用）は `02_analysis.md` のアーカイブに移した。

## 受け取った要求

**課題** ── お店で飲んだお酒のボトルをよく写真に撮るが、その場で美味しいと思うだけで、すぐに忘れてしまい自分の知識になっていない。

**目的** ── 飲んだお酒の特徴を覚えて把握し、お酒に詳しくなることで人生に幅を持たせたい。

**やりたいこと**

1. 飲んだお酒を**その場で調べて保存**したい（主な場面は店）
2. 入力は 2 経路：**ラベルの写真を撮る**／**メニューなどの名前・品種・特徴で検索する**
3. 写真や名前から **AI が銘柄情報を自動で調べて表示し、自分で修正もできる**ようにしたい
4. 記録には項目を持たせたい：**名前・品種・産地・味わい・蘊蓄的な特徴**、それと**備考**（自分の感想を書く欄。Q9 の回答で追加）
5. **過去に撮りためたラベル写真の取り込み**もしたい（一度きりではなく、あげそびれた写真を随時追加する）
6. **ログイン機能**を持たせ、ログインに意味があるようにしたい。**ログインなしでも「その場で調べる」は使える**が、保存はログインが必要
7. メニューから調べた場合は**銘柄の画像も取得**して付けたい（見つからなければ空欄でよい）。**自分で写真をアップロードして付けることもできる**

**対象** ── よく写真を撮るのは**ワインと日本酒**なので、この 2 種を深く扱う。ウイスキーなど他の種類は今回やらない。

※ 殴り書きにあった「enum で管理すればいい」「検索するだけならコストはさほど変わらない」は実現方法なので、要求から分けて `02_analysis.md` に記録した。

## 前提

（空欄にしない。聞いていないなら「未確認」、該当しないなら理由つきで「該当なし」）

- 想定規模：**複数ユーザー前提だが、当面の利用者は自分 1 人**（Q14 で確定）。新規の記録は月 1 回程度。写真のアップロードは一度きりの移行ではなく**随時**（撮ったのにあげていない写真を後から追加する。枚数は定めない。Q12 で確定）
- 保存期間：**確定**──無期限保存。自動削除はせず、ユーザーが個別に削除できればよい（Q15）
- アクセス境界：**確定**──複数ユーザーを前提に、自分の記録は自分にしか見えない（Q14）。**ログインなしでも「調べる」は使える**が、保存・一覧・検索はログインが必要
- 既存資産：システムは新規（既存なし）。ただし**過去に撮りためたラベル写真**が手元にあり、これが初期データになる
- 法規制・監査：法規制は該当なし。ただし**公開デプロイして複数ユーザーになれば、他者の個人情報**（メールアドレス・飲酒の履歴・写真の写り込み）**を預かる**ことになる。外部の AI サービスへの送信範囲は 03 の決めごとで絞る（無料枠は入力が学習に使われ得るため）

## 業務フロー

棚卸しと振り分けの過程は `02_analysis.md`。

```
[ゲスト（未ログイン）]
1.  ログインせずに、写真またはメニューの名前・品種・特徴で酒を調べ、結果を見る（保存はできない）

[記録者（ログイン済み）]
2.  アカウントを登録し、ログインする
3.  店で酒を注文し、ボトルが来たらラベルの写真を撮って登録する
4.  （メニューから調べる場合）酒の名前・品種・特徴を入力して調べる
5.  飲みながら、表示された銘柄情報（名前・種類・品種・産地・味わい・豆知識）と写真を見る
6.  調べた酒を「飲んだ記録」として保存する。飲まなかった酒は「気になる」として残す
7.  「気になる」の酒を実際に飲んだら、「飲んだ記録」に昇格させる
8.  推定の間違いを直し（AI が調べた欄も編集できる）、感想は備考欄に書いて、記録を確定する
    （その場でなくてもよい）
9.  確定後も内容を編集できる。必要なら AI に調べ直させる（AI の欄は上書きされる。備考欄は残る）
10. 写真の無い記録に、自分で写真をアップロードして付ける
11. 撮ったのにあげていなかった写真を、後日まとめてアップロードする
12. 溜まった未確定の記録を、後から順に確認して確定する
    （候補提示から、既存の銘柄への付け替えもここでできる）
13. 品種・産地・味わいで自分の記録を検索し、銘柄の一覧も眺めて振り返る
14. 不要になった記録・写真を個別に削除する。記録が 0 件になった銘柄も、一覧から削除できる

[システム]
15. 写真・入力テキストを知識源に照会し、返ってきた銘柄情報と写真を表示する
    （調べただけでは保存しない。ゲストも記録者も同じ）
16. 写真からの登録では、推定結果を「飲んだ記録」＋銘柄（未確定）として書き込む
    （店での最小操作＝撮って終わり、を成立させるため）
17. テキストで調べた結果は、記録者が保存（飲んだ記録／気になる）を選んだときに書き込む
18. 知識源が読み取れなかったときはその旨を示し、手入力での登録に切り替える

[知識源（外部の AI・検索）]
19. 写真・テキストから銘柄情報を推定し、可能なら銘柄の写真も探して返す
    （見つからなければ写真は空欄。推定を返す以外のことはしない）

[例外・ルール]
- 自分の記録は自分にしか見えない（複数ユーザー前提）。ログインなしでは調べるだけで、
  保存・一覧・検索は使えない
- ログインなしで調べた直後にログイン（登録）した場合は、調べ直さずにその結果を引き継いで保存できる
- 深く扱う種類はワインと日本酒。その他の種類は「その他」として浅く受ける
- 写真の出所は 3 通り：自分が撮った／知識源が探してきた／なし（空欄のままでよい）
- 同じ銘柄を別の日に飲んだら「飲んだ記録」は 2 件になる。銘柄の情報は共通
- 1 枚の写真に複数本のボトルが写っていても、1 本分の記録として扱う（切り出しはしない）
- 未確定の記録に期限や催促は無い。未確定でも一覧・検索に出る（未確定と分かる印つき）
- 保存は無期限。自動削除はしない。削除は記録者の個別操作のみ
- AI は必須ではない。最初から手入力でも登録できる
- AI の再照会は AI が調べた欄（味わい・豆知識など）を上書きし、その銘柄は未確定に戻る。備考欄（自分の感想）は上書きされない
- 昇格（気になる → 飲んだ）は訂正で戻せる（飲んだ → 気になる。飲んだ日は消える）
- 記録には飲んだ日と店名を持てる（どちらも任意）
- まとめ取り込みで作られた記録は、飲んだ日が不明のままでよい（写真の撮影日時が読めれば下書きとして入る）
- 写真からの登録は、照会に失敗しても（圏外・読み取り不能）写真と記録を残す。銘柄は仮の名前の未確定として後で直す。まとめ取り込みで読めなかった写真も同じ
- 記録が 0 件になった銘柄は削除できる（誤登録の掃除）。記録が付いている銘柄は消せない
- 退会（アカウント削除）は設けない。必要になったら運用で消す（順序：記録 → 銘柄 → パスワード・セッション → ユーザー）
```
